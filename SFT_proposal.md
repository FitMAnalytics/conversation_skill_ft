# Proposal: Fine-Tuning an Open-Source LLM for Outbound Sales

## Objective

Fine-tune an open-source LLM on outbound sales call transcripts from top-performing agents to build an AI agent that learns proven conversational strategies and combines them with the model's own reasoning capabilities to lead dialogue, identify customer needs, handle objections, and guide toward conversion.

## Why Fine-Tuning?

- **Behavioral internalization:** Fine-tuning embeds proven conversational strategies — objection handling, need discovery, closing techniques — directly into the model's weights, teaching the model *how* top agents think rather than just what they said.
- **RAG limitations:** A retrieval-based approach struggles to extract actionable patterns from long contexts where system prompts, transcript history, and multiple retrieved responses compete for the model's attention.
- **Consistency and efficiency:** The knowledge is in the weights, producing stable behavior across every call without dependency on retrieval quality, while reducing inference latency and token cost.

## Fine-Tuning Architecture

**Base Model:** GPT-OSS-120B — selected for its 120B parameter capacity to absorb complex conversational patterns and its strong native reasoning capabilities, which we leverage to enable strategic thinking before each agent response.

**LoRA Configuration:**

- **Attention-only adaptation:** LoRA targets attention layers (Q, K, V, O) which govern conversational focus and turn-level strategy; MLP/MoE layers are frozen as they are architecturally complex and store general knowledge we want to preserve.
- **Rank 32:** Balances expressiveness against overfitting — lower ranks risk underfitting complex multi-turn sales patterns, higher ranks add diminishing returns for our dataset scale.
- **Conservative learning rate:** Preserves the base model's pretrained reasoning and language capabilities while gently steering behavior toward sales-specific dialogue.
- **Distilled chain-of-thought:** Training data includes reasoning traces generated by a stronger teacher model (GPT-4.1), which analyzes each conversation turn and produces the strategic thinking — customer state assessment, objection identification, response planning — that the fine-tuned model learns to reproduce before generating each agent response.

**Training Data:** Transcripts are selected from converted outbound calls by top-rated agents, with sampling prioritizing broad coverage across objection types and conversation scenarios.

**Data Format:** Each training example consists of a system prompt defining the agent's role, a context block containing customer profile information, past conversation summary, and relevant product/campaign details (populated when available, reserved as placeholder otherwise), and the conversation history up to the customer's latest turn — the model then generates a reasoning trace followed by the agent's response.
